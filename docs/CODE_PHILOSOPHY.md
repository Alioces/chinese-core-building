# 代码编写规范

> **概述**：本规范定义项目代码编写的核心原则与实施标准。所有新增或修改的代码必须遵守以下规范，确保代码库保持简洁、可扩展、易维护。

> 优先复用旧代码。新代码开发时避免模块，类，直接的耦合。
> 代码规范严格遵循开闭原则。
> 反对过于复杂的架构和重复的样板代码。
> 反对在方法中出现多层嵌套的代码，代码嵌套的深度控制在4以下，嵌套层数过多应该提取子函数。更多从属一个功能的函数应该聚合成一个工具类
> 在完成每一项的代码编写任务后都需要编译确认不会出现语法错误，任何的代码都需要编写注释说明功能或者作用，以供学习参考。
> 注释标准应该使用对应的语言官方的注释风格，例如 java 语言的注释中的 Java 标准 Javadoc 文档注释风格

---

## 实施指南

### 1. 复用优先
- **检查清单**：编写新功能前，先搜索现有代码库是否有相似实现
- **判断标准**：若已有代码可覆盖 60% 以上需求，优先扩展而非新建
- **禁止行为**：为相似功能创建独立系统（如独立 BlockEntity/网络层/渲染器）

### 2. 开闭原则
- **扩展方式**：新增功能通过新增接口/类/枚举实现
- **禁止行为**：修改既有公共 API 的签名或行为
- **典型模式**：注册表模式（如 `GuiScreenRegistry`）、策略模式、工厂模式

### 3. 低耦合设计
- **模块隔离**：`main` 源集不引用 `client` 类，客户端可访问服务端接口
- **接口通信**：模块间通过接口而非具体类交互
- **禁止行为**：跨模块直接 new 具体实现类

### 4. 单一职责
- **判断标准**：一个类/方法若有超过 2 个变更原因，说明职责过多
- **拆分方式**：按变更原因拆分为多个类，通过组合或接口关联

### 5. 嵌套深度控制
- **上限**：方法内嵌套层级 ≤ 4 层（if/for/while/try 等）
- **优化手段**：
  - 卫语句（early return）替代深层 if
  - 提取子函数封装复杂逻辑
  - 使用 Optional/Stream 简化条件判断

### 6. 反对过度架构
- **判断标准**：若抽象层不能解决当前问题且无明确扩展计划，视为过度设计
- **原则**：简单问题用简单方案，YAGNI（You Aren't Gonna Need It）

### 7. 反对样板代码
- **识别标志**：复制粘贴超过 3 行相似代码
- **消除方式**：提取到基类、工具类、或泛型方法

### 8. 功能聚合
- **组织方式**：从属同一功能的函数聚合到工具类（如 `TextLineUtils`、`GuiLayoutHelper`）
- **禁止行为**：相关函数散落在多个不相关的类中

### 9. 不可变数据优先
- **首选**：Java `record` 类型
- **次选**：`final` 字段 + 构造函数初始化
- **禁止行为**：公开可变字段供外部直接修改

### 10. 组合优于继承
- **首选**：通过字段持有依赖对象（组合）
- **次选**：继承（仅当存在明确 is-a 关系时）
- **禁止行为**：为复用代码而继承（应使用组合）

### 11. 接口隔离
- **设计原则**：接口方法应属于同一职责范畴
- **判断标准**：若实现类必须实现不相关的方法，说明接口过大
- **拆分方式**：按职责拆分为多个小接口

### 12. 意图揭示命名
- **变量/字段**：名词短语，说明"是什么"（如 `editingLines`、`selectedIndex`）
- **方法**：动词短语，说明"做什么"（如 `saveEditToIndex`、`refreshEditFields`）
- **布尔值**：`is/has/can/should` 前缀 + 肯定形式（如 `isEnabled` 而非 `isDisabled`）
- **禁止行为**：单字母命名（循环变量 `i/j/k` 除外）、缩写歧义

### 13. 魔法数字具名化
- **提取标准**：所有非 0/1 的字面量都应提取为具名常量
- **命名规范**：全大写下划线分隔（如 `ROW_H`、`PANEL_PADDING`、`COLOR_PREVIEW_SIZE`）
- **组织方式**：相关常量聚合到类顶部或专用常量类

### 14. 失败快速
- **验证时机**：方法入口处验证参数合法性
- **异常信息**：明确告知问题原因和修复建议
- **禁止行为**：延迟到深处才暴露错误

### 15. 优雅降级
- **设计原则**：外部依赖失败时提供 fallback 行为
- **典型场景**：注册表未找到类型时返回默认实现
- **禁止行为**：直接抛出未捕获异常导致崩溃

### 16. 防御性编程
- **边界检查**：数组/集合访问前检查索引范围
- **输入校验**：对外部输入（用户输入、网络数据）做格式验证
- **副本返回**：返回内部集合/对象的副本，防止外部修改内部状态

### 17. Javadoc 标准注释
- **覆盖范围**：所有 `public`/`protected` 类、方法、字段
- **必要标签**：`@param`、`@return`、`@throws`（如有）
- **内容要求**：说明功能、参数含义、返回值、异常条件、使用示例（复杂 API）

### 18. 注释解释"为什么"
- **有效注释**：说明设计意图、边界条件、历史原因、性能考量
- **无效注释**：重复代码逻辑（如 `// 将 x 加 1`）
- **示例**：
  ```java
  // 使用 -angle 因为 MatrixStack.multiply 是右手系逆时针为正，
  // 而我们的旋转定义是顺时针为正（符合直觉）
  matrix.multiply(Quaternionf.rotateY(-angle));
  ```

### 19. 代码自文档化
- **优先手段**：通过清晰的命名、合理的结构、单一职责让代码自解释
- **注释定位**：注释是自文档化的补充，而非替代

### 20. 编译验证流程
- **时机**：每次代码修改完成后立即验证
- **检查项**：
  - 无语法错误（IDE 无红色波浪线）
  - 无未使用的导入
  - 无类型不匹配警告
- **环境限制**：若本地环境不满足编译条件（如 Java 版本），至少确保 IDE 诊断通过
